# Saved terminal-plan accounting and physical exposure

These derived records come from nine candidate witnesses and 72 checked plans. They disclose request-local aliases, relative times, phase durations, and displacements from reference geometry. Original coordinates, customer identifiers, private solver code, and full raw plans are excluded.

Run the standard-library arithmetic check:

    python3 check_records.py --output ../reproduced/witness_checks.json

It recomputes released task durations, 120 crane-chain sums, nine difference decompositions, contact-category totals, and release-to-reuse differences. It does **not** regenerate trajectories or independently validate restricted source plans. Their declared-scope checks are documented in the earlier `selective_reopening` release.

- `task_phase_timelines.csv`: relative task start/end and empty/hold/loaded phases.
- `crane_chain_accounting.csv`: initial gap, intertask gaps, task-phase sums, finishing task.
- `critical_chain_decomposition.json`: difference accounting for the same finishing resource/sequence.
- `terminal_plan_summary.json`: endpoint vectors and calendar-horizon checks.
- `geometry_displacements.csv`: centre/size differences and region/orientation change flags, not an absolute yard map.
- `adjacent_crane_exposure.csv`: X-centre separation over linear motions and stationary holds, from common origin through last completion, distinguishing task-phase and idle exposure.
- `spatial_reuse_exposure.json`: overlapping-footprint reuse with later entry decoded in the current request.

At b3-r006, 15028.943112 s less intertask gap offsets 1173 s more task duration, giving a 13855.943112 s endpoint gain. Gaps include all non-task intervals, not just rail waits. Rejected repair trials were not saved. Smaller examples reduce motion by 20 and 245 s. No recorded calendar-unavailability interval intersects these task horizons.

All 72 plans touch zero X separation; b2-r096 contacts are instantaneous. Other patterns also have positive-duration contact including task phases. These point-centre measurements do not represent crane-body safety.

All 24 reuse pairs start from **historical** released occupancy and end in current-request entry; minimum slack is 19330.834494 s. None tests a release generated by a carry in the current request. This cannot establish insensitivity to immediate release. No positive-clearance or delayed-release redecoding is claimed.


- `e33_positive_spacing_first_round.json` records a fresh batch-1 first-round formal-decoder sensitivity probe at 0 m and a synthetic 1 m minimum crane X separation. It does not re-decode the historical b3-r006/b3-r071 checkpoints, complete a batch rollout, or provide a field-safety threshold.
